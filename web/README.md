# 웹 패널 — 브라우저에서 시험 보기

브라우저 하나로 시험을 본다 — **왼쪽에 문제, 오른쪽에 진짜 터미널**, 버튼으로 채점.
채점은 각 세트의 `exam.sh` 가 그대로 한다 — 이 패널은 명령을 대신 실행하고 결과를 보여줄 뿐이라
**터미널 방식과 점수·기록이 100% 같다.**

## 띄우기 (VM 안에서)

```bash
cd ~/cka-lab && python3 web/server.py
```

출력에 나온 주소(`http://192.168.56.10:8080`)를 **맥/윈도우 브라우저**에서 연다.
VirtualBox 호스트온리 네트워크라 별도 포트포워딩 없이 바로 열린다.

```bash
python3 web/server.py --port 9000        # 포트 변경
python3 web/server.py --host 0.0.0.0     # 주소 자동 탐지가 실패할 때
```

파이썬 표준 라이브러리만 쓴다. pip 설치할 것이 없다.

## 화면

```
┌──────────────────────────┬─────────────────────────┐
│ Q1 조건대로 Pod 생성      │ [채점] [힌트] [넘어가기]  │
│  (문제 원문)              ├─────────────────────────┤
│                          │ ~/cka-lab/mock-2-2      │
│ 채점 결과  ✓ 3 / ✕ 7     │ $ kubectl run edge-cache│
│ 진행 현황 표              │   ...                   │
└──────────────────────────┴─────────────────────────┘
```

오른쪽은 **VM 의 실제 셸**이다 (PTY). `kubectl`·`vi`·`tmux` 다 된다.
셸은 시험장과 같은 상태로 뜬다 — kubectl 자동완성, `alias k`, `$do`(--dry-run=client -o yaml),
`$now`, vim 의 YAML 2칸 들여쓰기. (`_lib/exam-shellrc.sh`)
브라우저를 닫으면 그 셸은 종료된다 — 오래 도는 작업은 ssh 터미널에서 하거나 tmux 를 쓴다.
터미널은 페이지를 연 시점의 세트 폴더에서 시작한다. 세트를 바꿨으면 `재연결` 을 누르면 그 폴더로 다시 연다.
### 터미널 폭 조절

기본은 화면의 52% 지만 좁으면 넓히면 된다.

| 방법 | 하는 일 |
|------|---------|
| 가운데 세로 막대를 **드래그** | 문제/터미널 폭을 원하는 대로. 끄는 동안 `120×49` 처럼 현재 열×행이 표시된다 |
| 막대를 **더블클릭** | 기본 폭(52%)으로 되돌린다 |
| `⤢` | 터미널만 화면 전체로 (다시 누르면 복귀) |
| `⇄` | 문제와 터미널의 좌우를 바꾼다 |
| `A+` / `A−` | 글자 크기 — 작게 할수록 열 수가 늘어난다 |

폭·좌우·글자 크기는 브라우저에 저장돼 다음에 열 때도 유지된다.
폭을 바꾸면 셸에도 새 크기가 전달되므로(`TIOCSWINSZ`) `vi` 나 `top` 화면이 깨지지 않는다.
터미널이 필요 없으면 서버를 `--no-shell` 로 띄운다.

## 버튼

실제 CKA 시험도 같은 구조다 — 한쪽에 문제, 한쪽에 터미널.
터미널에서 `bash exam.sh check` 를 직접 쳐도 된다. 상태가 같은 곳(`work/.progress`)에 있어서 화면이 따라온다.

| 버튼 | 하는 일 | 터미널로 치면 |
|------|---------|---------------|
| 시험 시작 | 이전 리소스 정리 + 환경 준비 + 1번 문제 | `bash exam.sh start` |
| 채점 | 현재 문제 채점. 만점이면 자동으로 다음 문제 | `bash exam.sh check` |
| 힌트 | 힌트 표시 (리포트에 기록이 남는다) | `bash exam.sh hint` |
| EN / KO | 지문 언어 전환 (기본 영어) | `bash exam.sh lang ko` |
| 넘어가기 | 현재 점수로 확정하고 다음 문제 | `bash exam.sh skip` |
| ◀ ▶ · 진행 현황 표 클릭 | 다른 문제로 이동 (되돌아가기) | `bash exam.sh go 3` · `next` · `prev` |
| 리포트 보기 | 최종 리포트 | `bash exam.sh finish` |
| 원상복구 | 클러스터의 시험 리소스 삭제 + 기록 삭제 | `bash exam.sh clean` |

상단 드롭다운에서 세트를 고른다. 진행 상황은 `work/.progress` 에 남으므로
브라우저를 닫거나 터미널 방식으로 갈아타도 이어서 풀 수 있다.

**문제 사이는 자유롭게 오간다** — 실제 CKA 처럼 어려운 문제를 건너뛰고 나중에 돌아올 수 있다.
진행 현황 표에서 아무 줄이나 누르면 그 문제로 간다. 돌아와서 다시 채점하면 점수가 갱신되고,
문제별 소요 시간은 그 문제에 머문 시간만 누적된다 (다른 문제를 보는 동안은 세지 않는다).

## 속도 — 어디에 시간이 쓰이나

채점 시간은 거의 전부 `kubectl` 호출 대기다 (프레임워크 자체는 ~170ms).
그래서 **항목별 검사를 동시에 돌린다** — 순서·점수·화면은 순차 실행과 동일하다.

| | 순차(이전) | 병렬(지금) |
|---|---|---|
| 07-ingress Q1 (11항목) | 1,981ms | **693ms** |
| 06-networking Q1 (10항목) | 1,872ms | **665ms** |
| 시험 시작 — mock-3 정리 | 2,755ms | **1,073ms** |

```bash
EXAM_PARALLEL=0 bash exam.sh check      # 하나씩 실행 (디버깅용)
EXAM_PARALLEL_MAX=8 bash exam.sh check  # 동시 실행 수 (기본 4 — VM 메모리 고려한 값)
```

패널 쪽도 기다리지 않는다 — 명령 출력은 나오는 즉시 화면에 흐르고(롱폴링),
채점이 끝나면 대기 없이 결과가 뜬다 (버튼 클릭 → 첫 줄 65ms, 결과 594ms).

## 주의

- **인증이 없다. 그리고 브라우저 안에 진짜 셸이 있다.** 이 주소를 여는 사람은 곧 이 VM 의 셸을 쓰는 사람이 된다.
  실습 VM 안에서만 띄우고 공인 IP·포트포워딩으로 절대 외부에 열지 않는다.
  여럿이 쓰는 환경이라면 `--no-shell` 로 터미널을 끄고 문제·채점 패널만 쓴다.
- 한 번에 한 명령만 실행된다 (클러스터가 하나이므로). 실행 중에는 버튼이 잠긴다.
- 정답은 이 패널에 나오지 않는다. 힌트만 나온다. (정답은 각 세트의 `README.md`)

## 구조

```
web/server.py    표준 라이브러리 HTTP 서버 + WebSocket + PTY (exam.sh 실행, 셸 연결)
web/app.html     화면 한 장 (JS 프레임워크 없음)
web/vendor/      xterm.js 5.5.0 · addon-fit 0.10.0 (MIT) — 인터넷 없이 쓰려고 저장소에 넣었다
```

터미널은 `pty.fork()` 로 셸을 띄우고 WebSocket 으로 브라우저와 잇는다. WebSocket 핸드셰이크·프레이밍도
표준 라이브러리로 직접 구현했다 — 그래서 ttyd 설치나 pip install 이 필요 없다.

서버가 읽는 파일:

| 파일 | 내용 |
|------|------|
| `<세트>/work/.progress` | 진행 상황 (현재 문제·점수·소요 시간·시도 횟수·skip/hint) |
| `<세트>/work/.last-check.jsonl` | 직전 채점의 항목별 PASS/FAIL (`_lib/exam-lib.sh` 가 기록) |

서버가 부르는 `exam.sh` 명령: `start` `check` `skip` `hint` `finish` `clean` `reset`
그리고 패널 전용 `meta`(세트 정보) · `qtext`(장식 없는 문제 원문) · `hinttext`.
